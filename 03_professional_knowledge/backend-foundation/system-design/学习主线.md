1. **先学系统设计的判断框架**

你要先能拆问题：

- 用户是谁？
- 核心操作是什么？
- 读多还是写多？
- 数据量、QPS、延迟目标是多少？
- 可用性要求多高？
- 一致性要求多强？
- 哪些失败是必须处理的？
- 未来最可能增长的瓶颈在哪里？

这一步最重要，因为系统设计不是“用什么技术”，而是“为什么这个技术在这个约束下合适”。

2. **学数据模型和存储**

这是系统的地基。

重点学：

- OLTP vs OLAP
- 关系型数据库的索引、事务、隔离级别
- 主从复制、读写分离、分库分表
- NoSQL 的适用场景：KV、文档、列族、图数据库
- 数据冷热分层
- Schema 演进和数据迁移

核心问题：**数据如何被写入、查询、保护、迁移和恢复？**

3. **学缓存**

缓存不是“加 Redis 就快了”，而是引入了新的正确性问题。

重点学：

- Cache Aside、Read Through、Write Through、Write Back
- 缓存穿透、击穿、雪崩
- TTL、淘汰策略、热点 key
- 缓存一致性
- 本地缓存 vs 分布式缓存

核心问题：**允许多旧的数据？为了多快的访问？出了不一致怎么办？**

4. **学消息队列和异步化**

异步系统的本质是削峰、解耦和失败重试。

重点学：

- 队列、发布订阅、事件流
- 至少一次、至多一次、恰好一次的语义
- 幂等性
- 重试、死信队列、顺序消息
- 事件驱动架构
- Outbox Pattern

核心问题：**哪些事情不需要同步完成？重复执行会不会出错？**

5. **学分布式系统基础**

这是高级系统设计的分水岭。

重点学：

- CAP、PACELC
- 一致性模型：强一致、最终一致、因果一致
- 分布式锁
- Leader Election
- Consensus：Raft/Paxos 理解思想即可
- 时钟、顺序、幂等、去重
- 网络分区和超时

核心问题：**当机器之间不能可靠通信时，系统还能保证什么？**

6. **学扩展性和负载均衡**

重点学：

- 垂直扩展 vs 水平扩展
- Stateless 服务
- Load Balancer
- Partition / Sharding
- Consistent Hashing
- Rate Limiting
- Backpressure
- 降级、熔断、限流

核心问题：**流量增长 10 倍时，哪个部分先死？怎么让它不死？**

7. **学可靠性工程**

真正的系统设计不是画出正常路径，而是处理失败路径。

重点学：

- SLA / SLO / SLI
- Error Budget
- Timeout、Retry、Circuit Breaker
- Graceful Degradation
- Disaster Recovery
- Backup / Restore
- 多机房、多区域
- Observability：日志、指标、链路追踪

核心问题：**系统一定会失败，失败时用户和业务承受什么？**

8. **学典型系统案例**

不要一开始就背案例。先有框架，再看案例。

建议顺序：

- URL Shortener
- Rate Limiter
- News Feed
- Chat System
- Notification System
- Search Autocomplete
- File Storage
- Payment System
- Distributed Cache
- Distributed Queue
- Metrics / Logging System

每个案例都按同一套模板练：

- 需求
- 规模估算
- API
- 数据模型
- 高层架构
- 关键瓶颈
- 一致性选择
- 失败处理
- 扩展方案
- Trade-off
